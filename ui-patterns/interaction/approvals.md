# Approval Interaction Pattern

## Use when

A user or agent proposes a consequential action requiring explicit human control.

## Required information before approval

Show:
- action;
- target;
- material consequence;
- key inputs;
- policy/risk reason;
- who is requesting;
- what happens after approval.

## Actions

At minimum:
- approve;
- reject/cancel.

Where useful:
- request changes;
- edit;
- defer;
- escalate.

## Key rule

> Approval UI must communicate consequence, not merely ask “Are you sure?”.
